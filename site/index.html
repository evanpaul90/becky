What is Becky?

Becky is a multi-agent coding OS that combines BMad pipelines, Karpathy-style wiki memory, closed learning loops, and dual-runtime coordination between Claude and Codex.

Instead of one monolithic AI assistant that forgets everything between sessions, Becky deploys a squad of 7 specialized agents governed by 10 immutable rules. Every mistake becomes a rule. Every rule compounds intelligence. The system literally gets smarter with each project.

The Pipeline

Two modes, one protocol. Each step has a gate -- nothing advances without verification.

1
PM_JOHN

Product Brief + PRD

PM runs 4-5 elicitation methods, produces product brief, then full PRD with acceptance criteria for every feature.

GATE: PRD passes adversarial review
2
ARCH_WINSTON + UX_SALLY

Architecture + UX Design

Architect produces ADRs, data models, API contracts. UX agent produces interaction specs, design tokens, screen flows.

GATE: Architecture passes implementation readiness check
3
SM_BOB

Sprint Planning + Story Creation

Epics decomposed into stories with full context. Each story file contains everything an agent needs to implement it independently.

GATE: Stories trace back to PRD requirements
4
DEV_AMELIA + QA_QUINN + VERIFY_01

Implementation + Verification Loop

Dev implements, QA validates with Playwright tests, Verifier confirms DONE/VERIFIED/AUDITED. Learning loop encodes lessons.

GATE: Runtime evidence required for DONE status
1
SCRIBE_01

Codebase Indexing + Documentation

Scribe indexes the existing codebase, generates project context, maps architecture patterns, and populates the wiki.

GATE: Project context validated against actual codebase
2
PM_JOHN + ARCH_WINSTON

Gap Analysis + Change PRD

PM identifies what needs to change, Architect maps impact across the existing system. Change-set PRD with surgical scope.

GATE: Change scope verified against existing architecture
3
DEV_AMELIA + QA_QUINN + VERIFY_01

Surgical Implementation + Regression Tests

Dev makes targeted changes. QA validates no regressions. Verifier confirms runtime behavior matches before/after expectations.

GATE: Zero regression, runtime proof of change

Anti-Inflation Protocol

Three tiers of truth. No agent can claim DONE without runtime evidence. No exceptions.

State Evidence Required Example
DONE Runtime artifact: API response, DB query result, browser screenshot proving the feature works "Called API, got 200, verified row in DB"
VERIFIED Acceptance criteria reviewed line-by-line with code citations for each point "AC says X -- see file.ts:42"
AUDITED File existence confirmed, LOC counted, function names match spec "Function exists at line 608, 90 LOC"
verdict.yaml
story: "F7-guest-stay-panel"
status: DONE
evidence:
- type: runtime
proof: "Playwright screenshot: check-in -> folio -> checkout flow"
- type: db_query
proof: "SELECT * FROM folios WHERE booking_id=42 -- balance: 0, status: settled"
verifier: VERIFY_01
rule_violations: 0
